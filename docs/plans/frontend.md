# Frontend Ecosystem Viewer — Implementation Plan

Concept: `frontend/SPEC.md` (viewer purpose + backend contract) + `docs/archive/world-readiness.md §5` (gap
audit). Wire contract: `docs/core/data-contracts.md §4/§10` (`WorldFrame`, Animal/Plant lifecycle events).
This file is the **roadmap** for replacing the hardcoded decorative mockup with a real ecosystem
render — terrain (river/grass/forest), flora (trees/bushes, growth stages), fauna (animals with
movement / attack / death motion), agents, ambient weather — plus the **asset pipeline** that feeds
it. It does not restate the SPECs; per-module detail lands in `frontend/SPEC.md` +
`frontend/src/render/SPEC.md` + `frontend/src/assets/SPEC.md` once the Open Questions resolve.

## 0. Decisions locked

- **Read-only viewer, SSE-driven.** All render input arrives via `GET /sse` (`WorldFrame` +
  lifecycle events) and REST initial-load. The frontend never invents simulation state; anything not
  streamed is not drawn (scent, cost fields). Env-off neutrality stays: no `WorldFrame` → the
  social-only render, byte-identical.
- **One shared world→canvas transform** (D11): agents, animals, flora, terrain cells map through ONE
  `buildTransform`; positions stay continuous floats; the terrain grid is a render *index*, entities
  never snap to cells.
- **Single source of truth = `useWorld` reducer.** Render functions are pure
  `(state, clockMs) → pixels` — animation takes an **explicit time input** (no hidden mutable
  clocks), so Vitest can assert any frame.
- **Sprite/style mapping is data, not code** (D10 mirror). `species → pose → asset` and
  `TerrainID → style` live in a **manifest module** (a typed data table + fallback chain), never in
  `if (species === 'wolf')` switches — species, ActionIDs, and TerrainIDs are open content
  (`fauna/SPEC.md`, `content/terrain.yaml`); a new species must render (via fallback) with **zero
  code edits**.
- **`canvasRenderer.ts` splits** (522 lines > ~400 rule): per-layer modules under
  `frontend/src/render/`, one SPEC for the folder. The uncommitted prototype's module-level
  `new Image()` singletons + hardcoded species/action substring switches are **redone** per the
  manifest/loader design (they violate the "no module-level mutable state" invariant).
- **Poses are a closed render vocabulary; ActionIDs are open.** The manifest maps open-content
  ActionIDs onto a small fixed pose set via an ordered pattern table + default — the render layer
  never enumerates ActionIDs. (Q2 RESOLVED: `idle|walk|run|eat|attack|dying`.)
- **Assets = PNG spritesheets** (Q1 RESOLVED, human choice over the SVG recommendation): one sheet
  per species under `frontend/public/assets/`, fixed frame size, one row per pose, N frames per
  row played at a manifest-declared fps; missing pose rows fall back (`pose→walk→idle→glyph`).
  Example sheets are generated by a checked-in dev script (`frontend/dev/generate-spritesheets.mjs`),
  so placeholders are reproducible and replaceable by real art without code changes.
- **Interactive camera** (Q6 RESOLVED, human choice): top-down view anchored to
  `RenderConfig.bounds` at load, then **wheel zoom in/out** (cursor-anchored), **drag pan**, and
  **click-to-follow**: selecting an entity locks the camera centre to it until deselect/manual pan.
  One camera state feeds the single shared transform (D11 unchanged).

## 1. Current baseline (what already works)

- **Data/state layer is done and ahead of the renderer**: `useWorld.ts` reduces `AgentFrame`
  (sparse per-agent deltas; replaced the removed full-roster `TickDone` frame, data-contracts §4) +
  `WorldFrame` into `WorldState.agents / animals / flora / climate`; `types.ts` carries every env
  shape (`AnimalState{pos,species,action,heading,stamina}`, `PlantState{pos,species,stage,width}`,
  `ClimateState`, `TerrainDelta`, `RenderConfig`). Bootstrap is snapshot-first with a Redis
  stream-cursor replay boundary + `world_revision` readiness marker (lossless late join, regen
  completion detection — the mechanism lives in `frontend/SPEC.md` §Bootstrap/§New-map flow).
  SSE connect/reconnect (`useSSE.ts`) works.
- **Render layer is a mockup**: `canvasRenderer.ts` draws a **hardcoded decorative map** (fake
  quadratic river, forests, buildings in canvas pixel coords, wrong "(1000,1000)" label) + agent
  dots; `buildTransform` auto-fits the agent/object bbox and ignores `RenderConfig`.
- **Uncommitted prototype (input, not settled design)**: 64×64 top-down SVGs in
  `frontend/public/assets/animals/` (deer walk/run/eat, wolf walk, tree, bush, agent) generated by
  root `generate_svgs.js`; `drawFlora`/`drawAnimals` that rotate by `heading` and dim by `stamina`;
  `frontend/mock-server.js` serving fake snapshot + SSE frames.
- **Backend WI-P4 is NOT implemented yet**: nothing emits `WorldFrame` today; `platform/api` has
  **no initial-terrain endpoint** (contract gap → Q5). Until WI-P4 lands, development runs against a
  mock (Q7) and the live viewer stays social-only (neutrality invariant).

## 4. Render purity & testability (the frontend's "determinism")

- Every render/animator fn is pure: `(slice, transform, clockMs) → draws/values`; sprite cache is
  injected, not global; `Math.random()` is forbidden in render paths (FX curves are
  time-parametric). Same state + same clock ⇒ same frame.
- Reducer stays the only writer of world state; `fx[]` entries carry absolute timestamps and are
  pruned by the reducer (on later events), never mutated by the render layer.
- Unknown species / ActionID / TerrainID **must** render via the fallback chain — a fixture with
  `species:"unknown_beast"` draws the category glyph, never throws.

## 5. Performance

- Budget: ~200 animals + ~500 plants + terrain grid (≈64×64 cells at 8.0 world units on the 512
  world) at 60fps RAF on a laptop.
- Terrain renders to an **offscreen canvas** re-blitted per frame; re-rasterized only on
  `terrain_delta`/wear change (cells are sparse deltas). Flora sorts/draws once per frame (mostly
  static); per-entity `drawImage` for fauna is fine at this count.
- SVG sprites decode once at preload (they rasterize on first `drawImage`; cache per size if it
  measures slow).

- **Q2 — Pose vocabulary + ActionID mapping** `RESOLVED: closed pose set + pattern table`.
  Poses = `idle | walk | run | eat | attack | dying`; ordered `ACTION_POSE_RULES` patterns
  (`hunt|attack→attack`, `flee→run`, `graze|eat|drink→eat`, locomotion→walk, default `idle`);
  new action content renders via patterns/default with zero code/asset edits (D10 mirror).
- **Q3 — Movement animation model** `RESOLVED: adaptive lerp`. Interpolate pos/heading from the
  previous to the latest frame over the measured inter-frame interval; heading via shortest arc;
  snap is the degenerate case when frames outpace RAF. Walk↔run refinement may read displacement
  rate.
