# Design — 개념 모델 & 확정 결정 (rationale)

> *무엇*은 `docs/PRD.md`, *이름*은 `docs/glossary.md`. 이 문서는 *왜*와 *건드리면 안 되는 결정*.

## 1. 개념 모델 (한 장)
에이전트는 **가치**를 올리거나 지키려 **목표**를 띄우고, 정적 행동 그래프 위에서
**HTN으로 방법을 고르고 GOAP로 빈칸을 채워** 경로를 짠다.
어떤 경로가 *보이고 골라지는지*는 수치가 만드는 **게이트·비용**이,
*추상 높이와 예측 능력*은 **지능**이 정한다.
물건은 목표가 아니라 **수단**이고, 평판은 **분포된 의견**이며,
범죄·정치·제도는 코딩하지 않고 **가치 기울기 충돌**에서 떨어진다.

### 1.1 의사결정 루프
`지각 → 가치 평가(아는 객체별 EffValue) → 목표 중재(가장 값진 것) → 계획(HTN+GOAP+forward-sim+게이트) → durative 실행 → 상호작용(신호) → 신념·평판·위임 갱신`

### 1.2 상태 3중
모든 수치는 **실제(god)** / **자기 주관(`ToM[self]`, 결정이 읽음)** / **타인 주관(관찰자별)**.
자기인식은 **행위로 per-stat 보정** — 과대평가는 시도→실패→자기교정, 과소평가는 비가시→self-sealing(영영 안 풀림).

### 1.3 가치 = 끝, 물건 = 수단
가치는 `{Dimension, Ref(포인터), Posture, Setpoint}`. 자기 허기·아이 행복·조망·치안이 *하나의 평면 집합*.
각 에이전트는 *아는 객체*마다 `Standing × Salience` 가치를 가진다. 모르는 객체는 없다.

### 1.4 지능 = 추상 사다리 다이얼
高지능: 가치 수준 작동, 수단 자유 대체, 멀리 봄(forward-sim), 타인 `unmet-need` 깊이.
低지능: 물건 고착(재바인딩 불가), 짧은 시야(예측·보급 안 함), 타인 `mood` 표면.

### 1.5 예측 보급 (forward-sim)
need마다 **rate 상수**만 두면, 플래너가 플랜 시간선을 따라 need-궤적을 forward-roll →
도중 setpoint 위반 예측 시 **보급 하위목표를 자동 삽입**. 수량은 `예상소모 − 도중가용` 파생.
같은 forward-sim이 `Mood`의 '예상 진척'도 공급.

### 1.6 창발 제도
역할(촌장)은 자료형이 아니다. 분산 미충족 가치 → 위임이 최저비용 → 평판으로 같은 대상 수렴(급하면 투표 가속) →
`RelyOn` 클러스터 결정화. 권력·정당성은 파생·동적(점유자 Soul × 사회 신뢰 되먹임).

## 2. 확정 결정 (ADR) — 어기려면 이 문서를 먼저 고치고 사람 승인
| # | 결정 | 왜 (rationale) |
|---|------|----------------|
| D1 | 가치가 끝, 물건은 수단 | 추상 목표(행복·안전)가 실제 동기. 물건을 목표로 두면 대체·계획이 막힘 |
| D2 | 메타 시스템·제도 하드코딩 금지 | 범죄·정치·역할은 가치 충돌의 부산물. 하드코딩하면 창발이 죽음 |
| D3 | 행동은 원자·방법만 정의, 경로는 창발 | 조합 폭발을 선형 작성으로. 트리를 손으로 안 그림 |
| D4 | 비용·게이트는 *태그*에서 유도 | 행동마다 bespoke 함수 쓰면 작성량 폭발 |
| D5 | 효용(가치) ↔ 계획(HTN+GOAP) 분리 | "원함"과 "얻는 법"을 섞으면 둘 다 망가짐 |
| D6 | 평판을 단일 값으로 저장 안 함 | 평판 = 관찰자별 `ToM[C]` 분포. 파벌별 모순 평판이 핵심 창발 |
| D7 | 개별 스킬 없음 | 능력 = 기본 능력치 조합 **수식(§6 DSL, 데이터)** — 행동별 가중치는 데이터 수식이지 저장된 스킬·Go 함수가 아님(매번 base에서 재계산). **기본 능력치 자체는 가변**: 그 스탯을 *쓰는* 행동을 하면 일반 컨디셔닝으로 늚(어떤 행동이 어떤 스탯을 쓰는지는 §6/태그 파생, rate=balance, `range` 상한)·나이로도 변동(§7) — 단 **행동별 저장 스킬은 없음**('손재주 행위→Dexterity↑'는 *일반 스탯* 상승=일반화, 스킬 트리 아님). '숙련가'는 편중된 삶에서 **창발**(D2). 스탯은 content로 자유 추가(D10); 새 `kind`는 엔진 의미를 지녀 스키마+엔진 확장(순수 데이터 아님). 스킬 나열은 폭발+일반화 실패 |
| D8 | 자기인식 = `ToM[self]`, 행위로 보정 | 과소평가의 self-sealing 비대칭이 임포스터·소심을 공짜로 생성 |
| D9 | 객체에 미래 수치 필드 없음 | 보급은 need-rate × 예상시간 forward-sim 파생. 객체엔 충족량(공급)만 |
| D10 | 수치·행동·게이트는 `content/` 데이터 | 코어 무수정 확장. AI는 작은 데이터 diff만, 스키마가 검증 |
| D11 | 자유 좌표 + 공간 해시(+ 내비 비용장 격자 *인덱스*) | 자유(타일 구속 X) + 성능(국소 쿼리) 둘 다. **격자는 인덱스이지 월드가 아님**: 에이전트 위치는 항상 연속 `float`, 격자는 근접 쿼리(spatial hash)·길찾기 비용(navmap)을 *계산*하는 보조 색인일 뿐. 에이전트를 칸에 스냅하거나 로직을 타일 순회로 굴리는 것은 여전히 금지(§5 참조) |
| D12 | 결정론(시드 주입, map 순회 금지, ID 고정 순서 적용) | 회귀·리플레이·디버깅의 토대 |

## 3. 막다른 목표 = 드라마의 엔진
경로가 없거나 게이트로 다 막히면 코핑 캐스케이드:
예산 확대 → 목표 재바인딩(모조품·대체, *低지능은 막힘*) → 성향별 코핑(longing/무의식 저장→resentment/무기력) →
urgency·타인가치·아드레날린 상승 시 양심 임계↓ → 범죄 가시화.

## 4. 미해결 (계수·후반, P1을 막지 않음)
forward-sim 정밀도/주기; 항 라이브러리·rate·α·β·λ 구체값 + 자동 튜닝 지표; 자존 방어기제 trait 형태;
역할 검출 임계·승계; 미래 투영을 언제 일반 lookahead로 승격; 생애주기 *계수*(노화 곡선·세대 상속률 — 사이클 자체는 §7 확정);
멀티스레드 계획 결정론; 후각 그라디언트·LoS 구현 비용; durative 중단 시 진행도 보존 정책.

## 5. 맵 / 내비게이션 — "길은 그리지 않고 창발한다"
> 상세 구현 로드맵·통합 변경점은 `docs/map-plan.md`. 여기는 **개념과 rationale**(왜)만.

공간을 단순 거리에서 **지형·장애물·길이 있는 비용 공간**으로 확장한다. D1~D12를 깨지 않는다.

- **substrate (D11 보충):** 연속좌표는 유지하고, 그 위에 **내비게이션 비용장(cost field)을 격자 _인덱스_**로 둔다 — `spatial`(근접)과 같은 부류의 보조 색인. 길찾기는 이 비용장 위 **결정론적 A*/Theta\***(연속적 경로 모양 유지). 에이전트는 칸에 스냅되지 않는다.
- **지형 (D4/D10) = 바탕재료(속성 프리셋) + 속성 벡터:** 지형은 코드가 아니라 **데이터**. **바탕재료**(`sand·soil·river·mountain·sea`)는 *속성 기본값 묶음(프리셋)*일 뿐, **변형은 속성 오버라이드**(별도 타입 아님). **속성:** `grainSize`(고운/굵은)·`moisture`(마름↔젖음↔물에잠김)·`temperature`(달궈짐)·`depth`(수심)·`slope`(경사)·`salinity`(염도). 예) river=depth중간·moisture최대·salinity0, mountain=slope높음, sea=depth·salinity높음; '고운 모래'=sand+grainSize↓, '물기많은 진흙'=soil+moisture↑(climate가 굴림), **swamp=soil+높은 moisture**. **모든 파생**(이동 cost·통과 게이트[강 `depth`↔Swim, `slope`↔등반]·climate 전이·flora 적합도·식수[`salinity`])**= 속성 위 §6 수식**(특별 케이스·bespoke 함수 없음, D4). 못 넘는 지형은 길찾기가 우회.
- **초목 = terrain이 아니라 object (flora):** 나무·풀·식물은 지형 위에 놓이는 **오브젝트**다. '숲'=나무 객체 군집, '늪'=흙+높은 `moisture`(둘 다 별도 terrain 타입 아님). **그늘:** 식물 객체가 주변에 그늘을 드리워 **시야(LoS) 감소**(perception) — '어두운 숲'은 그늘 중첩으로 창발(terrain 'light' 속성 없음). 식물의 생성·성장·고사·자원(베리)·그늘은 **flora 서브시스템**.
- **건물 (D2):** 벽/집은 통행 불가 footprint, 문은 그 안의 통행 가능 포털. 정착지는 `Build`의 부산물로 **창발**(제도/도시계획 하드코딩 금지, D2).
- **길 = 창발 상태, object 아님 (D1/D2/D3):** 길은 content에 그리지 않는다. navmap의 **셀 단위 sparse `wear` 필드**가 길이다. 통행하면 `wear↑`→`cost↓`(밟힌 trajectory에만, region 전체 아님), 매 틱 decay→안 쓰면 **소멸**. `cost = base × f(wear)`. "TTL object" 직관은 이 **decay/refresh 의미론**으로 흡수(저장은 격자, 길찾기와 일관). 장애물이 생기면 우회하고 옛 길은 decay로 사라짐.
- **길닦이 = 도구적 서브목표 (D1, terminal value 아님):** 길닦이는 새 가치가 아니라, **기존 가치를 위한 수단**이다. 거래(Social/획득) → 같은 corridor 반복 이동 → 누적 cost → "이 경로를 provision하면 미래 plan이 싸진다" → `Pave` 서브목표. 이는 **D9를 need 대신 _경로 cost_에 적용**한 것 — "길을 식량처럼 provision한다". 두 층위:
  - **창발(공유지):** traffic이 곧 `wear`라 자주 다니면 cost가 자동으로↓ — 누구도 "결정"하지 않아도 길이 남. (~80%가 공짜.)
  - **의도적 ROI:** "예상 통행 N × Δcost > pave 비용"일 때 `Pave`를 **forward-provisioned 서브목표**로 삽입. 이건 플래너에 *지연·간접 보상을 보는 도구적 통찰*을 줘야 함(GOAP는 현재-plan만 최적화) — 맵보다 큰 플래너 확장. (`map-plan.md §6`.)
- **길닦이의 사회적 부산물 (창발, D6):** `Pave`를 `cooperative`/공공재 태그로 두면 관찰자가 ToM[paver]를 올려 **평판**이 이동하고 **가십**의 소재가 된다. Standing을 중시하는 에이전트는 이를 또 하나의 desire-driven 동기로 Pave할 수 있다. 평판/가십은 paver의 *목표*가 아니라 타인이 관찰한 *결과*다(D1: 모두 원하는 것에서 파생).
- **비용의 귀결:** MoveTo의 실제 비용/시간/스태미나가 경로에 비례. `bindTarget`은 유클리드가 아니라 **경로비용 최근접** 자원을 고름(강 건너 가까운 베리 < 이쪽 길로 닿는 베리). 즉 공간이 의사결정에 실제로 개입.
- **지형 = 정적 아님, 상태를 가진다 (climate):** 셀/region이 `moisture` 등 상태를 갖고, **기후(강우·기온)**가 이를 밀어 임계 넘으면 **상태/타입 전이**(가뭄→젖은 흙이 마름, 장마→흙이 젖음/물에 잠김; 초목은 별도 flora 객체로 고사). 전이 규칙도 **데이터**(D4/D10, bespoke 금지). ⇒ 지형은 더 이상 "정적·1회 송신"이 아니라 `wear`처럼 **동적 델타**(→ `map-plan.md`/`data-contracts.md` 갱신 대상).
- **다중 주기 갱신 (성능 × D12):** 갱신 비용을 주기로 분산 — 건물 footprint=즉시(이벤트), `wear`=매 틱, 지형 전이=느린 bulk(`tick % N`). 병렬은 *read* 또는 비겹침 파티션 *write*를 고정순서 merge만.
- **결정론 (D12):** A* 동률은 셀ID로, wear deposit은 apply 단계 직렬 누적, decay/전이는 고정순서 1패스. 갱신 트리거는 `tick` 파생(절대 wall-clock 아님). map 순회로 로직 굴리지 않음.

## 6. 수식 DSL — stat 계산식은 데이터다 (D4/D7/D10)
게이트·행동 비용·**능력 합성**·**행동 outcome**은 Go 함수가 아니라 **선언적 수식**으로 쓴다. 한 평가기를 전 모듈이 공유(gate의 `expr`를 산술까지 확장).
- **피연산자:** stat ID(에이전트 값으로 해석) · 숫자 리터럴 · 문맥 변수(`terrain.depth`, `self.stamina` 등) · **술어 함수**(불리언, 게이트·문 접근정책용) `has(itemID)`(소지)·`isOwner`·`paid(toll)` — 모두 식별자.
- **연산:** 산술 `+ - * /`·괄호(→ 수치); 비교 `> < >= <= == !=`(→ 불리언); 논리 `& | !`(→ 불리언).
- **출력 타입 = 문맥:** 게이트/시도 임계 = 불리언, 능력 합성·비용·"건널 수 있는 폭" = 수치.
- 예: 능력 `STR*0.5 + AGI*0.3`; 시도 `(STR*0.5 + AGI*0.3 > 0.5) | (AGI > terrain.depth)`.
- **결정론(D12):** 고정 연산자 우선순위, RNG 미포함(필요시 주입), 미정의 식별자는 **로드 시 검증 실패**(D10). 형식만 고정이고 변수명은 자유.
- **평가기 위치:** 한 평가기를 **`engine/expr`(L0 leaf, core 타입만 의존)**가 제공하고 gates·climate·actions·economy가 추상 `Context`(stat 값·소지·소유·문맥 변수 조회)를 넘겨 공유한다 — DSL 드리프트 방지(glossary "one shared evaluator"). gates의 boolean tree는 이 평가기의 boolean 부분집합.

## 7. 생애주기 — 사망 × 번식은 하나의 사이클
- **행동 = 결정적 공급만이 아니라 위험·단계적 outcome을 가질 수 있다:** 실제 스탯 + (인지/실제) 지형을 **§6 수식**으로 평가, **durative 중 per-tick 재평가** → 진행 / 중단(회항) / 실패. 강을 건너다 자원이 바닥나고 회항할 여력도 없으면 **사망**.
- **시도(인지) vs 판정(실제) 2단계 (D8):** *시도*는 인지 능력(`ToM[self]`)·인지 지형(강 폭이 지능·자신감으로 다르게 *보임*)으로 결정; *판정*은 실제값으로. 과신→시도→사망, 과소→비시도(self-sealing). 이미 plan(신념 읽기)/apply(실제 적용) 2단계 위에 그대로 얹힌다(새 기계 최소).
- **Stamina = need 아님 (이미 존재):** `Body.Stamina`(Mood/Adrenaline류 동적 상태, sleep/rest로 회복 — glossary 기존 항목). 새 스탯도 새 need도 아니다. 추가되는 건 **결합 규칙뿐**: Stamina↓ → Rest/Sleep need 강도↑(기존 Rest 재사용).
- **사이클:** 사망과 **번식**이 함께 인구 생애주기를 이룬다. 자식·세대는 §1.3의 가치 대상(예: '아이 행복')으로 이미 모델에 있음 — D1과 충돌 없음. 노화 곡선·세대 상속률 등 *계수*는 §4.

## 8. LLM 경계 — 런타임 0, author-time만
- **런타임(시뮬 틱):** LLM 0, 완전 결정론(D12/NFR). 틱은 어떤 외부 호출도 기다리지 않는다.
- **author-time(콘텐츠 파이프라인):** LLM이 콘텐츠를 *생성*해도 된다. sim이 "적합 콘텐츠 없음" **gap 이벤트**를 emit → **queue** → 사용량(load/quota) throttle 워커가 자동 생성 → **스키마 검증(D10)** → DB/content append → 다음 run이 결정적으로 read. 창발 자산은 run 사이에 누적되되 틱은 절대 안 막힘. 생성기는 `backend/tools/`(엔진 밖).

## 9. 사유자산 · 소유 · 돈 — 경제 primitive (창발 경제의 최소 토대)
제도("통행료/시장")는 코딩하지 않는다(D2). 아래 *primitive*만 두고, 행동은 가치·평판·코핑에서 창발한다.
- **돈 = `currency` item_kind (데이터, D10):** 창발 상품화는 가독성↓이라 포기. 돈은 인벤토리의 특수 아이템일 뿐 — 이동은 기존 **trade**(Signal/ClaimedValue) 재사용. "널리 받아들여짐"은 행동으로 창발.
- **소유 = object→`owner` 관계 (신규 primitive):** `Build`가 builder를 owner로 set. **양도(판매)·상속 가능** — 양도는 ownership을 옮기는 trade. **상속은 §7 사망과 결합**(죽으면 소유물이 상속/무주물/분쟁으로 — 드라마 훅). *공동소유는 frontier로 park*(공유자산 거버넌스 = 그 자체로 창발 영역; 단일소유+양도+상속으로 toll·사유 드라마는 충분).
- **접근 통제 = '소유된 포털'(문):** 길은 여전히 창발 `wear`(object 아님). 소유·과금되는 건 길목의 **문(구조물, map-plan M3 포털)** 이다. 잠긴 집 문(사생활)과 통행료 문(상업)은 **같은 primitive** — 주인이 통제하는 포털.
- **개폐/통과 = §6 수식 (soft lock):** "열 수 있나/지날 수 있나"를 §6 DSL로 — `has(key) | STR > door.lockStrength | paid(toll) | isOwner`. ⇒ 자물쇠는 **절대벽이 아니라 stat 경합** → 힘센 자의 **강제 침입이 창발**(D2 범죄), 통행료 미지불 시 우회/항의. M2의 agent별 Caps 게이트 위에 그대로 얹힌다.
- **구조물 파괴 = '사망의 객체판':** 문/벽/집은 `integrity`(HP) 상태를 갖는다(지형 `moisture`처럼). 강제 개방/공격은 `STR > lockStrength`형 **§7 위험·durative 행동**으로 per-tick `integrity`를 깎고, 0이면 **파괴 = world 제거 + footprint un-stamp**(map-plan M3 `RemoveObject`) → navmap이 길목을 **영구 개방**으로 리루트. 진짜 새 기계는 `integrity` 필드뿐 — 제거·리루트·소유주 원한(Vindictiveness)·창발 범죄(D2)는 §7/M3/가치·ToM에서 합성된다.
- **결합:** 상속은 §7(생애주기)와, 통행료는 §5(지형 길목·문)와 맞물린다. 상세 로드맵·미해결은 `docs/economy.md`.
